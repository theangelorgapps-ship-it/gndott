# Practical auth/API audit — 8 November 2026

Scope: viewer authentication/session/API code and the active administrator authentication/central authorization guard. The security-auditor and secure-api-builder skills were applied. No live OTP/reset request, setup message, test email, production data write, dependency installation or deployment was performed by this audit. Cloudflare setup and deployment belong to the integration owner.

## Authentication and recovery behavior

The same D1 user IDs, credentials and role ownership remain. Viewer and admin sessions/challenges/rate-limit tables and host-only cookies are separate. Current account status, ban/deletion flags and normalized-email uniqueness are checked before sessions are used. Password changes/reset revoke both realms through the existing compatibility triggers. No signup/OTP path can assign an administrative role. The existing verified Google linking rules and Apple state/PKCE flow are preserved.

Canonical origin configuration is restricted to `halobox.tv` for the viewer and `fort.halobox.tv` for administration (plus each realm’s own legacy Worker origin during callback migration). Cross-realm configuration, credentials, paths, query strings and insecure schemes are rejected. Host headers cannot choose the production auth origin. Localhost always remains local and cannot activate email.

Recovery uses six-digit, five-minute, hashed, single-use OTPs with three incorrect attempts. The plugin validates password rules and purpose; application hooks add live eligibility and abuse checks. Both existing password hashes and IDs are retained. Viewer `/forgot-password` and administrator `/login` now offer reset codes; unavailable delivery is reported honestly. Cloudflare’s structured `EMAIL.send({from,to,subject,text})` API is used with separate sign-in/reset subjects. No test invokes a real binding.

## Residual risks and limits

- Playback URLs are still normal CDN assets. Server-side API redaction closes disclosure before entitlement, but previously learned URLs or sharing by an entitled viewer require CDN token authentication/domain policy to prevent reuse. That configuration was not changed. Historical PPV records were preserved; provenance of old manual grants was not audited or deleted.
- Full administrators remain broadly privileged. Permission-table settings are not a complete enforced authorization matrix, and existing admin audit events do not consistently cover every mutation. Demo reads can expose administrator-visible data; the business must decide whether that role should exist against production at all. This patch prevents demo writes without changing current role ownership.
- Exact configured ad URLs create an administrator trust boundary. No generic arbitrary URL fetch remains, but DNS resolution of administrator-selected hosts is not independently pinned. Cloudflare edge request quotas/rate policy and media provider settings were not assessed by offline tests.
- Profile count/minimum checks still use separate read/write operations; concurrent requests can race those product limits. Ownership predicates remain enforced. Broad public list endpoints and library reads are not fully paginated. These are operational hardening items rather than proven account-crossing failures.
- Unknown/disabled email recipients return generic success without delivery; synchronous provider latency may still reveal whether a message was sent. Durable queued sending with uniform response timing would reduce this signal. Recovery attempt limits reduce brute-force abuse but do not replace Cloudflare bot controls.
- Dependency advisory scans cannot prove packages are safe. The source scan is pattern-based, not a repository-history or cloud secret inventory audit. No exhaustive penetration test, real provider consent, real deliverability test, production write, cloud IAM review, or full payment/store audit was performed.
- Deployment must coordinate `BETTER_AUTH_URL`, DNS/custom domains and registered Google/Apple callbacks. User-requested delivery should only be enabled with the verified sender binding. The integration gate owns live state; all proof here is offline and sends no email.
